# レポっとアーカイブのビューア

ビルド不要の静的ページです。Vue 2、MapLibre GL JS 5.24.0、PMTiles 4.4.1をCDNから読み込みます。

画像は、JSONの `filename` を次のURLの末尾に付けて取得します。ビューアの写真一覧と地図のポップアップはサムネイルを使います。

| 種類 | URL |
| --- | --- |
| 元画像 | `https://data.cocolab.jp/repot/{filename}` |
| サムネイル | `https://data.cocolab.jp/repot-thumb/{filename}` |

リポジトリのルートで次を実行し、`http://localhost:8765/` を開いて確認できます。

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs
```

## 地図の配信先

地図はMapLibre GL JSとPMTilesで描画します。配信先は [static/js/map-config.js](static/js/map-config.js) で変更できます。

| 設定 | URL |
| --- | --- |
| スタイル | ビューアと同じサーバーの `static/map/japan.json` |
| 日本の詳細表示 | `https://tiles.yukimat.jp/japan.pmtiles` |
| 国外・広域表示 | OpenFreeMapのTileJSON `https://tiles.openfreemap.org/planet` |

スタイルJSONは [static/map/japan.json](static/map/japan.json) を編集し、ビューアのファイルと一緒に公開します。配信先はモジュールのURLから解決するため、localhostやサブディレクトリへの設置でも同じ構成で動作します。地図サーバー上の `japan.json` は読み込みません。

国外は [OpenFreeMap](https://openfreemap.org/) の世界ベクトル地図で表示します。APIキーや利用者登録は不要です。日本と同じOpenMapTiles形式なので、現在の配色・地名の表示設定を共通で使います。写真のマーカー、ポップアップ、一覧との連動も国内外で同じです。

ズーム10以降は日本のPMTilesを優先し、その範囲外や収録されていないタイルを世界地図で補います。ズーム9以下の広域表示は世界地図を使い、日本の周辺地域が欠けるのを防ぎます。表示中のタイルだけを取得し、地図の切り替えで写真や選択状態を初期化しません。片方の配信元で通信エラーが起きた場合は、利用できる側で補います。OpenFreeMapは外部サービスのため、国外の表示はその配信状況に依存します。

配信情報のURLは `map-config.js` の `worldTileJSONURL`、日本のPMTilesを優先するズームは `japanMinZoom` で変更できます。TileJSON内の日付付きURLは自動で取得するので、更新のたびにコードを変更する必要はありません。`worldTileJSONURL` を空文字列にすると、日本のPMTilesのみを使う構成に戻せます。地図には両方の配信元・データの帰属表示を載せています。

背景地図は写真マーカーを見やすくするため、白に近い陸地と水色を使い、海岸線・道路・緑地・建物を判別しやすいコントラストにしています。地名は通常の太さの小さめのグレーにし、市区町村・細かい地名をズーム段階に応じて表示します。駅名はズーム13以降に小さなグレーの文字だけで表示します。線路はズーム13以降に細い淡色線で表示し、鉄道の枕木模様、施設アイコン、道路番号、立体建物などは省いています。スプライト画像は使わず、前の配布スタイルにあった不足画像の警告も発生しません。地図データの権利表示は保持します。文字フォントは引き続き `tile.openstreetmap.jp` の `Noto Sans Regular` を利用します。

タイルサーバーから読み込むのは `japan.pmtiles` だけです。PMTilesにはHTTPS・CORS・Range配信が必要です。スタイルJSONは同一Originから配信するためCORSの設定は不要です。設定例と確認手順は、公開用フォルダの外にある [タイルサーバーの設定](../server-config/README.md) にまとめています。既に設置済みの `.htaccess` はそのまま利用できます。

地点はGeoJSONのシンボルレイヤーにまとめて描画し、既存のSVGアイコンのサイズ・アンカー位置を維持します。重なる地点も従来と同じく表示し、クラスタリングは行いません。期間変更・データセット変更は地図の表示位置を維持したまま反映します。初期位置は従来と同じ岡山付近で、初期ズームは512pxタイル基準の11（従来のLeafletの256pxタイル基準の12に相当）です。

緯度・経度が数値でない場合、範囲外の場合、`(-1, -1)`・`(0, 0)` の欠損値の場合は地図に表示しません。位置情報のない写真も一覧やダウンロードには残します。WebGLを利用できない場合や地図の通信に失敗した場合は案内を表示し、写真一覧・期間選択・データ取得の機能を使い続けられます。通信失敗時は「再試行」から地図を読み直せます。

## 操作

画面幅1200px以上では従来のPC画面、1200px未満ではスマホ向けの画面になります。切り替え時も、選択したデータセット・表示期間・地図の位置を維持します。

SafariのURLバー・ステータスバー・キーボードで利用できる領域が変わる場合は、VisualViewportの高さと位置をCSS・JSで共有し、ヘッダー・シート・メニュー・ダイアログを表示領域に収めます。下部の安全余白は写真一覧のスクロール領域内に設けます。ページ自体のピンチズームではレイアウトを組み直しません。

PC画面は左メニュー、上部の情報バー、左右に並ぶ地図と写真一覧で構成されます。地図と一覧の境界線はドラッグで幅を変更できます。境界線にフォーカスして、左右矢印キー、Home、Endでも調整できます。

スマホ向けの画面では次の操作ができます。

- 上部中央のデータセット名を押すと、同じ枠内に一覧が開きます。
- 右上の情報ボタンから、システム概要、データの利用条件、「データの使い方」を表示できます。データの使い方には、JSONの取得URL・項目・日時や欠損値の扱い、サムネイルと元画像のURL、JavaScriptでの取得例をまとめています。PCでは左下のメニューから開けます。
- ロゴ・データセット選択・情報ボタンは同じ高さです。地図の拡大縮小ボタンは表示せず、ピンチ操作で拡大縮小できます。地図の権利表示は左端で上から下へ読む向きにし、背景を透過します。初期のシート位置と上部ボタンの間で上下中央に固定し、シートを動かしても移動しません。
- 写真一覧の上部にあるハンドルを上下にスワイプ・ドラッグすると、一覧の高さを3段階に変更できます。ハンドルは高さ44pxの操作領域の中央に配置し、タップでも変更できます。
- ハンドルにフォーカスして、上下矢印キー、Home、Endでも高さを変更できます。
- 写真は基本2列、画面幅700px以上では3列になります。
- 一覧上部に写真枚数、JSONのダウンロード、表示期間を表示します。期間は日付入力・年・全期間から指定できます。
- 写真を押すと地図の対象地点へ移動し、地図のマーカーを押すと一覧の対象写真へスクロールします。
- データセットの指定は `#komaruKurage` などのハッシュと、従来の `?h=komaruKurage` に対応します。両方指定した場合はハッシュを優先します。
- ダイアログを開くとURLも変わり、`#license`（利用条件）、`#about`（システム概要）、`#developer`（データの使い方）、`#period-setting`（表示期間の変更）から直接開けます。閉じるボタン・枠外タップ・Escで閉じると、選択中のデータセットのURLへ戻ります。データセット未選択の場合はハッシュだけを除きます。

## テスト

リポジトリのルートから実行します。外部通信や追加パッケージは不要です。

```sh
node --test tests/viewer.test.cjs tests/archive-map.test.cjs tests/hybrid-basemap.test.cjs
```

シートのスワイプ・高さ制限・画面回転、URLバー・キーボードによる表示領域の変化、ページのピンチズーム、履歴復帰、PCとスマホの切り替え、PCの左右幅調整、データセット切替、期間の絞り込み、地図と一覧の連動、メニュー操作、既存URLの動作を検証します。

地図のテストでは、PMTiles参照の補正、座標の順序・欠損値、非同期のアイコン読込中の切り替え、期間変更、地図クリックと写真の連動、ポップアップの安全なテキスト表示・画面内への移動、アニメーション中断、通信失敗後の再試行を検証します。

国内外のタイル選択、広域表示、未収録タイルの補完、配信元の通信失敗、移動中のリクエスト中止も検証します。
